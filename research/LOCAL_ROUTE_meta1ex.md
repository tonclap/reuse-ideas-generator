# Локальный маршрут как опциональный: llama.cpp + Gemma 4 12B — Алексей

Разведка от **01.09.2026**. Тот же вопрос, что в [T-02 (#17)](../../../issues/17) и
[RECIPE_CALL_meta1ex.md](RECIPE_CALL_meta1ex.md) — проходит ли изображение вместе со
схемой в одном вызове, — но для локального OpenAI-совместимого сервера вместо OpenRouter.

> **Связка проходит.** Проверено прогоном 01.09.2026: изображение и `response_format` со
> схемой уходят в одном вызове, ответ валиден по схеме, картинка действительно прочитана.
> Маршрут при этом **не решение**: D-010 оставляет транспортом OpenRouter, локальное плечо
> там отклонено. Это тестовый путь, заведённый Алексеем осознанно.

## Сервер, на котором проверено

```
http://192.168.1.38:8080        llama.cpp build b10731-0eadefebd
модель  gemma-4-12B-it-qat-UD-Q4_K_XL.gguf  (unsloth/gemma-4-12B-it-qat-GGUF)
/v1/models → capabilities: ["completion","multimodal"]
/props     → modalities: { vision: true, video: true, audio: true }
```

Проверять `/props` перед прогоном стоит всегда: без загруженного `mmproj` зрения нет, а
**отказ будет молчаливым** — см. ниже, это здесь главная ловушка.

Скорость: 87 токенов/с, полный вызов с картинкой — **7–12 секунд**. Изображение из `input/`
занимает всего ~130 промпт-токенов. Авторизация не нужна, заголовок один:
`Content-Type: application/json`.

Поле `model` сервер **игнорирует**: приняты и полный путь из `/v1/models`, и `"gemma"`, и
пустая строка — во всех трёх случаях `http=200` и один и тот же ответ. Загружена одна
модель, выбирать нечего. Для кода это значит, что маршрут задаётся адресом сервера, а не
полем `model`.

## Форма `response_format` — тут была ошибка, исправляю

Формы **две, и работает не та, что в README llama.cpp**:

| форма | как выглядит | результат |
| --- | --- | --- |
| вложенная (как у OpenRouter) | `{"type":"json_schema","json_schema":{"name":…,"strict":true,"schema":{…}}}` | **схема соблюдена** |
| плоская (из README llama.cpp) | `{"type":"json_schema","schema":{…}}` | `http=200`, схема **молча проигнорирована** |

Плоская форма не даёт ни ошибки, ни предупреждения: приходит валидный JSON, но с полями,
которые модель придумала сама. На `item_15` она вернула `рама`, `паспарту`, `содержимое`,
на `item_03` — `композиция`, `объекты`, `освещение`. Оба ответа не проходят валидацию по
схеме. Воспроизведено дважды, на обоих фото.

**Хорошая новость для [T-03 (#12)](../../../issues/12) и [T-09 (#20)](../../../issues/20):**
форма `response_format` у локального маршрута и у OpenRouter **совпадает**. Ветвить в коде
нечего — один и тот же объект уходит в оба. Кодирование изображения тоже совпадает: тот же
элемент `content` с data URL `data:image/jpeg;base64,…`.

## Вторая ловушка: модель рассуждающая

Ответ приходит в двух полях, и содержательное может оказаться пустым:

```json
{ "choices": [ { "finish_reason": "length",
    "message": { "content": "", "reasoning_content": "…200 токенов размышлений…" } } ] }
```

Рассуждение идёт **до** ответа и тратит тот же бюджет `max_tokens`. При `max_tokens: 200`
до JSON дело не дошло вовсе: `content` пуст, `finish_reason: "length"`. На схеме из трёх
скалярных полей ушло **550–870 completion-токенов**, из которых на сам JSON — три строки.

Отсюда два следствия для T-09:
- `max_tokens` брать с большим запасом; **2000** отработали устойчиво, 200 — провал;
- пустой `content` при `finish_reason: "length"` — это **не отказ схемы и не отказ зрения**,
  а исчерпанный бюджет. Различать обязательно, иначе диагноз будет неверным.

## Что получено

Фото — не `item_10`/`item_13` (зашиты в пункт 3 критерия [D-011](../COMMON_DECISION.md)).
Схема игрушечная, та же, что в основном рецепте, и с будущей схемой T-03 не пересекается.

`item_15`, рамка-коллаж в пузырчатой плёнке на полу:

```json
{ "dominant_color": "белый, коричневый", "object_count": 4, "is_indoor": true }
```

`item_03`, пять бокалов на подоконнике против света — контрольный вызов:

```json
{ "dominant_color": "белый, зеленый, прозрачный", "object_count": 5, "is_indoor": true }
```

Оба проверены библиотекой `jsonschema` — валидны. Ответы **различаются**, пять бокалов
сосчитаны верно: схема заполнена по изображению, а не наугад.

Что картинка прочитана по-настоящему, видно из свободного ответа (плоская форма, без
ограничения схемой) на `item_15`: модель перечислила Эйфелеву башню на двух снимках,
Пизанскую башню, логотип `CASA` на карточке, пузырчатую плёнку и деревянную поверхность.
Всё это в кадре есть.

На `item_15` два маршрута разошлись в счёте: OpenRouter дал `object_count: 1` (рамка как
предмет), локальный — `4` (снимки внутри рамки). Расхождение фиксирую как факт; чей счёт
уместнее — вопрос [T-14 (#26)](../../../issues/26), а не этой проверки.

## Как поднят сервер

```bash
llama-server \
  -m gemma-4-12B-it-qat-UD-Q4_K_XL.gguf \
  --mmproj mmproj-F16.gguf \
  --host 0.0.0.0 --port 8080
```

- `--mmproj` — без него зрения нет. В репозитории модели лежат `mmproj-F16.gguf`,
  `mmproj-BF16.gguf`, `mmproj-F32.gguf`. При запуске через `-hf` проектор подтягивается сам.
- `--host 0.0.0.0` — по умолчанию `llama-server` слушает `127.0.0.1` и снаружи невидим.
  На первой попытке проверки маршрут был недоступен именно так: хост отвечал на ICMP и
  отвергал все TCP-порты.

## Воспроизвести руками

```bash
cd /path/to/reuse-ideas-generator
B64=$(base64 -w0 input/item_03.jpg)

curl -s http://192.168.1.38:8080/v1/chat/completions -H "Content-Type: application/json" \
  -d "$(cat <<JSON
{
  "model": "gemma-4-12B-it-qat-UD-Q4_K_XL.gguf",
  "temperature": 0, "max_tokens": 2000,
  "messages": [{ "role": "user", "content": [
    { "type": "text", "text": "Опиши это изображение по схеме. Отвечай только про то, что видно в кадре." },
    { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,$B64" } } ] }],
  "response_format": { "type": "json_schema", "json_schema": {
    "name": "smoke_probe", "strict": true,
    "schema": { "type": "object",
      "properties": {
        "dominant_color": { "type": "string" },
        "object_count":   { "type": "integer" },
        "is_indoor":      { "type": "boolean" } },
      "required": ["dominant_color","object_count","is_indoor"],
      "additionalProperties": false } } }
}
JSON
)" | jq -r '.choices[0].finish_reason, .choices[0].message.content'
```

Пробник со всеми шагами (доступность → модальности → обе формы схемы → два фото) лежит вне
репозитория: `local_probe.sh`. Код по D-003 идёт через PR, а эта задача — прямой push.

## Чего проверка не покрывает

- **Схема из трёх скалярных полей.** Вложенные объекты и массивы (идеи → шаги, оценка
  затрат) не проверялись — схеме T-03 нужен свой прогон на этом маршруте.
- **Одно изображение в сообщении.** Несколько за раз не пробовал.
- **Ни цена, ни качество.** Это T-11/T-14. На локальном плече цена вообще не в долларах,
  и метрика T-14 к нему в лоб не применяется.
- **Устойчивость.** По одному-двум вызовам на фото; повторяемость на длинной серии и
  поведение при насыщении контекста не мерялись.
