# Приёмка схемы на маршруте T-02

Третий пункт условия готовности **T-03** ([#12](https://github.com/tonclap/reuse-ideas-generator/issues/12)) — «маршрут из T-02 её принимает».
Прогон **01.09.2026, 22:30 MSK**, по рецепту Алексея
([research/RECIPE_CALL_meta1ex.md](../research/RECIPE_CALL_meta1ex.md)): `google/gemini-2.5-flash-lite`,
провайдер `google-ai-studio` закреплён, `allow_fallbacks: false`, `require_parameters: true`,
`temperature: 0`, `max_tokens: 3000`. Ключ мой (D-027 ред. 2), стоимость двух вызовов —
**$0.00051**.

Рецепт прямо оговаривал, что проверял он схему из трёх скалярных полей, а вложенные объекты и
массивы на маршруте не проходили. Здесь проверены именно они.

## Ответ на вопрос пункта: маршрут схему принимает

| | `item_06` | `item_11` |
| --- | --- | --- |
| `finish_reason` | `stop` | `stop` |
| валиден по схеме (`jsonschema`) | да | да |
| стоимость | $0.00027237 | $0.00023797 |

Вложенность отрабатывает целиком: массив `ideas` → объект идеи → массив `steps`, объект `cost`
→ массив `materials`. Ни одного нарушения строгого режима, `["string","null"]` возвращается как
настоящий `null`, а не строкой `"null"`.

**Фото выбраны так, чтобы не трогать `item_10` и `item_13`** — они поимённо зашиты в пункт 3
критерия D-011, и рецепт T-02 отдельно предупреждает не расходовать их до настоящего прогона.
`item_06` даёт полную вложенность, `item_11` (макросъёмка без предмета в кадре) бьёт по краю:
категория и уточняющий вопрос.

Промпт был намеренно минимальный — «Заполни схему по этому фото. Отвечай только про то, что
видно в кадре». System prompt это T-04 ([#18](https://github.com/tonclap/reuse-ideas-generator/issues/18)), его ещё нет. Поэтому прогон — чистая
проверка того, **что удерживают одни только `description` схемы, без промпта.**

## Что сработало

**Дословный префикс в `visible_detail` — 5 из 5.** Все пять идей начали поле точной копией
записи из `visible_details`. Механизм машинной сверки «идея ↔ видимая деталь», ради которого
поле и вводилось, держится без единого напоминания в промпте. Это главный размен всего PR, и
он оправдался.

## Что не сработало — и это результат, а не сбой

Запреты, сформулированные в `description` как «не пиши так», не удержались **ни одного раза**:

1. **`visible_details` вернул «коляска в хорошем состоянии»** — ровно ту формулировку, которую
   описание поля приводит как пример того, чего писать нельзя.
2. **`first_action` вернул «Определить желаемую форму и размер»** — снова дословно тот вид
   ответа, который описание называет не-действием.
3. **`clarifying_question: null` на `item_11`.** В кадре нет предмета: ни границ, ни масштаба.
   Эталон T-05 требует здесь вопрос обязательно, а `category` вместо `undetermined` пришла
   `other` — то есть механизм честного «не опознаю» не включился сам.
4. **`uncertainty_note: null` на обоих фото.** На `item_11` модель уверенно предложила
   «нарезать материал на заготовки», приняв макроснимок фактуры за доски. Это ровно та
   галлюцинация, от которой поле и заводилось.

**Вывод для T-04.** Схема делит запреты на два класса. Что можно выразить **структурой**
(обязательное поле, enum, «начни дословной копией») — держится само. Что выражено только
**просьбой внутри `description`** — не держится вообще, и переносить это в system prompt
придётся целиком, а не «дублировать на всякий случай». Для пунктов 2 и 3 критерия D-011 это
значит, что без T-04 они не берутся в принципе: на одной схеме модель уверенно отвечает там,
где должна спрашивать.

Отдельно: **прогон не является данными для D-011.** Это техническая приёмка формы; ни один
ответ отсюда не идёт в замер, и оба фото остаются неизрасходованными для настоящего прогона.
