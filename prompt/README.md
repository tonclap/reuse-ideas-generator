# System prompt v1

Задача **T-04** ([#18](../../../issues/18)), роль 1 — Выдача. Волна 1а: приёмка этой задачи — уже обращения к модели.

| Файл | Что это |
| --- | --- |
| [`system_v1.txt`](system_v1.txt) | ровно тот текст, который уходит в `messages[0].content` с `role: system` |

**Пользовательское сообщение текста не содержит** — в нём только изображение (`image_url`, data URL по рецепту T-02). Всё, что сервис требует от модели, живёт в system prompt и в `description` схемы; отдельной инструкции на каждый снимок нет, иначе прогон стал бы невоспроизводимым от кадра к кадру.

## Откуда взялась форма

Приёмка схемы T-03 ([`schema/ACCEPTANCE.md`](../schema/ACCEPTANCE.md)) дала вывод, вокруг которого построен весь этот файл: **держится структура, а не просьба.** Требование «начни дословной копией видимой детали» сработало 5 из 5, а запреты, сформулированные внутри `description` как «не пиши так», — 0 из 4.

Поэтому промпт написан не как свод пожеланий, а как набор проверок:

- **Фильтр идей стоит первым разделом**, до порядка работы и до описания полей. Идея, не прошедшая проверку, не пишется вовсе — формулировка «вычеркни целиком, а не оговорись» появилась после того, как первая версия принесла совет разобрать ноутбук с оговоркой про осторожность.
- **Запрет назван вместе с тем, что разрешено.** «Корпус электроники не вскрывается» дополнено «разрешено всё, что делается с закрытым корпусом»: запрет без границы модель обходит, сузив себя слишком сильно или не поняв, где она.
- **Каждое правило проверяемо на готовом ответе.** «Начинается с „определить“ — переформулируй», «подставь другой предмет того же класса», «в кадре нет предмета известного размера — значит размер неизвестен». Это то, что модель может применить к своему черновику, а не настроение, в которое её просят прийти.
- **В конце — чек-лист из семи вопросов**, повторяющий те же проверки в форме «да/нет».

## Как доводился: пять прогонов на трёх фото

Маршрут по рецепту T-02: `google/gemini-2.5-flash-lite` @ `google-ai-studio`, `allow_fallbacks: false`, `require_parameters: true`, `temperature: 0`, `max_tokens: 3000`, схема через `response_format`. Фото — `item_15` (состояние очевидно), `item_01` (решающее не видно), `item_14` (назначение неясно). Полные ответы финальной версии — в [#18](../../../issues/18).

| Прогон | Что сломалось | Чем чинилось |
| --- | --- | --- |

## Что держится на финальной версии

На трёх фото, все три ответа валидны по схеме, `finish_reason: stop`:

- дословный префикс в `visible_detail` — **7 идей из 7**;
- уточняющий вопрос стоит там и только там, где его требует эталон T-05: `item_01` — про загрузку системы, `item_14` — про высоту в сантиметрах, `item_15` — `null`;
- `uncertainty_note` заполнена на обоих фото, где кадр не даёт уверенности, и `null` там, где даёт;
- ни одной идеи со вскрытием корпуса, продажей или сдачей;
- ни одного `first_action` вида «определить» / «изучить» / «решить».

## Что не держится — и это вход в следующие задачи

- **Идеи для `item_01` остаются идеями про класс вещи.** «Использовать как внешний монитор», «сделать цифровую фоторамку» — верно для любого ноутбука без видимых повреждений. Фильтр «подставь другой предмет того же класса» модель проходит формально: привязывает идею к признаку, который её не определяет. Пункт 1 критерия D-011 по такому фото не берётся, и промпт это не лечит — на кадре просто нет ничего, за что зацепиться, кроме отсутствия царапин.
- **Материал и размер модель придумывает.** На `item_14` керамика названа пластиком, на `item_15` появилось «одно отверстие размером 10×15 см» — числа, которых в кадре нет ничем не измерить. Проверка масштаба заставила спросить про размер, но не запретила выдумывать его в `visible_details`.
- **`first_action` у разных идей совпадает**, когда все идеи начинаются с одного и того же действия («вынуть фотографии из рамы»). Формально верно, для человека бесполезно.

Всё это — материал для T-15 и для v2 промпта, а не повод править файл сейчас: правки, сделанные по трём кадрам, будут подгонкой под три кадра.

## Ограничение, которое надо знать

Прогонов на фото здесь по одному, а D-014 требует двух независимых. Это доводка промпта, а не замер: **ни один ответ отсюда не идёт в данные для D-011**, и `item_10` / `item_13`, поимённо зашитые в пункт 3 критерия, не расходовались (T-04 их не трогает по условию задачи).
