# reuse-ideas-generator

По фото ненужной вещи — конкретные идеи, как её **повторно использовать или переделать**.
Продажу и утилизацию сервис не предлагает: продукт сознательно сужен до реюза
([D-009](COMMON_DECISION.md)).

Заодно это площадка для эксперимента: двое пробуют парную агентную разработку и идут
от творческого хаоса к MVP — [INTENTION.md](INTENTION.md).

**Стадия: build** ([D-020](COMMON_DECISION.md)). Explore закончен, две независимые разведки
лежат в [research/](research/) — но кода сервиса всё ещё нет, а критерий «прототип ✓» ни разу
не проверен реальным прогоном модели. Переход к сборке этот риск не снял, а перенёс.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env            # сюда свой ключ OpenRouter (D-027 ред. 2)
python main.py --dry-run        # план прогона без единого вызова
python main.py                  # все фото из input/
python main.py item_01 item_03  # только названные
```

`main.py` прогоняет `input/` по маршруту из `config.yaml` через OpenRouter
([D-010](COMMON_DECISION.md)) и складывает **сырые** ответы в `output/<run-id>/` вместе с
логом `run.json` (маршрут, время, стоимость, ошибки). Повторный запуск предыдущий прогон не
затирает; лог переписывается после каждого фото, поэтому прерванный прогон остаётся
читаемым.

Маршрут можно переопределить, не трогая конфиг: `--model`, `--provider-tag`,
`--reasoning-effort` и `--no-temperature`. Это нужно замеру цена/качество (T-14,
[#26](../../issues/26)), где один набор идёт по 2–3 маршрутам; фактический маршрут пишется в
`run.json`, так что прогон остаётся воспроизводимым. Модель выбирается замером, а не
назначается заранее.

Два последних флага — не удобство, а условие измеримости части маршрутов. `temperature`
принимают не все эндпоинты, и вместе с `require_parameters: true` неподдержанный параметр
отбивает вызов `404` ещё до модели. Маршруты reasoning-класса без заданного бюджета
рассуждения уводят в него весь `max_tokens` и возвращают пустой `content` — деньги списаны,
ответа нет; такой случай пишется в лог отдельной причиной `empty_content_length`, а не общим
«ответ не валиден».

Коды возврата: `0` — все ответы валидны, `1` — прогон прошёл, но часть ответов невалидна или
упала, `2` — прогон не начался (нет фото, нет ключа, не читается промпт или схема).
